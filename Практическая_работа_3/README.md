## Исходные данные

Учебная версия датасета Iris: 150 цветков трех видов (setosa, versicolor, virginica) и 4 размера каждого цветка. В файл специально добавлены ошибки, поэтому в нем 185 строк вместо 150.

## Что сделано

### 1. Изучение данных

Файл загружен через `pd.read_csv`, просмотрены `head(10)`, `info()` и список колонок. Уже здесь видно, что колонка длины чашелистика прочитана как строка, а не как число, и в двух колонках есть пропуски.

### 2. Названия колонок

Исходные названия были в разном стиле: `Sepal Length Cm`, `Sepal Width (Cm)`, `Petal-Length-Cm`, `Petal-WIDTH(Cm)`, `SPECIES`. Все колонки переименованы в snake_case с единицами измерения: `sepal_length_cm`, `sepal_width_cm`, `petal_length_cm`, `petal_width_cm`, `species`.

### 3. Найденные проблемы

| Проблема | Где | Сколько |
|---|---|---|
| Текст в числовой колонке (`??`, `very_long`) | sepal_length_cm | 2 |
| Пропуски | sepal_length_cm / petal_length_cm | 15 (+2) / 14 |
| Разные написания вида (`virginica`, `versi color`, `setsoa`, пробелы) | species | 13 |
| Неизвестный вид `unknown` | species | 1 |
| Значения в миллиметрах вместо сантиметров | unit = mm | 10 строк |
| Повторяющиеся строки | id | 35 лишних строк |
| Ошибки ввода (пропущена запятая: 13 вместо 1.3) | petal_width_cm | 5 |

### 4. Очистка данных

- **Текст в числах.** `pd.to_numeric(..., errors="coerce")` превращает `??` и `very_long` в пропуски, колонка становится числовой.
- **Названия видов.** `str.strip()` убирает лишние пробелы, `replace` заменяет все варианты на правильные названия Iris-setosa, Iris-versicolor, Iris-virginica.
- **Миллиметры.** Для строк с unit = mm все размеры делятся на 10.
- **Неизвестный вид.** Строка с `unknown` удалена: без вида она для обучения бесполезна.
- **Дубликаты.** Сначала исправлены виды и единицы измерения, иначе одинаковые цветки не считались бы дубликатами. После `drop_duplicates()` осталось 149 строк, все id уникальные.
- **Пропуски.** Строки не удалялись, чтобы не потерять около 20% данных. Пропуски заполнены медианой отдельно по каждому виду, потому что размеры у видов сильно отличаются.
- **Выбросы.** По правилу IQR найдены значения ширины лепестка 13, 18, 24, 25 см. Это пропущенная запятая, поэтому они поделены на 10. Еще одна такая ошибка (2.0 см у setosa, у которой ширина лепестка не больше 0.6) видна только при проверке внутри вида, она тоже исправлена. Значения ширины чашелистика 2.0 и 4.1 до 4.4 формально выходят за границы IQR, но это настоящие размеры цветков, их оставили.

Для проверки очищенные данные сверены с оригинальным Iris из sklearn: все значения совпали, кроме заполненных пропусков.

### 5. Преобразование признаков

- **Типы.** Колонка unit удалена (после перевода везде cm), вид переведен в тип `category`.
- **Масштабирование.** `StandardScaler` приводит каждый признак к среднему 0 и стандартному отклонению 1.
- **Кодирование.** Вид закодирован числами 0, 1, 2, как в sklearn.

### 6. Отбор признаков

Колонка id удалена, это просто номер строки. По матрице корреляций и `SelectKBest` сильнее всего с видом связаны длина и ширина лепестка (корреляция 0.95 и 0.94), слабее всего ширина чашелистика. Признаков всего 4, поэтому для модели оставлены все четыре.

### 7. Разведочный анализ (EDA)

Классы сбалансированы: 49, 50 и 50 цветков. Построены гистограммы, ящики с усами по видам и диаграмма рассеяния размеров лепестка. Выводы:

- setosa полностью отделяется от других видов по размерам лепестка;
- versicolor и virginica немного пересекаются, virginica в среднем крупнее;
- по ширине чашелистика виды различаются слабо.

### 8. Подготовка к обучению

- Данные разделены на train / validation / test в пропорции 70 / 15 / 15 (104, 22 и 23 строки) с сохранением доли видов (`stratify`).
- Все шаги очистки собраны в функцию `clean_iris()`, которая из сырого файла получает ту же таблицу, что и ручная очистка.
- Собран конвейер `Pipeline`: заполнение пропусков, масштабирование и логистическая регрессия. Точность на validation 0.91, на test 0.91.
